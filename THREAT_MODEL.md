# Модель угроз VOIDTWEAKS

## Активы

| Актив | Почему важен |
| --- | --- |
| Лицензионные ключи | Дают доступ к PRO; утечка = бесплатное использование и потеря выручки |
| HWID и привязка к ПК | Ограничивают передачу ключей третьим лицам |
| Аккаунты (email, пароль) | Вход в кабинет, история заказов, привязка ключей |
| Платежи и заказы | Подделка суммы/статуса = выдача ключа без оплаты |
| Админ-панель | Полный доступ к пользователям, ключам и выручке |
| Установщик Windows | Подмена = выполнение кода на ПК пользователя |
| Секреты (service_role, ЮKassa) | Полный доступ к данным и платежам |

## Акторы

- **Гость** — не авторизован, может только читать публичные страницы.
- **Покупатель** — авторизованный пользователь, покупает и активирует ключ.
- **Обычный пользователь** — пытается получить чужой ключ/заказ или
  обойти HWID.
- **Внешний атакующий** — перебор, флуд, подделка запросов, XSS/CSRF,
  кликджекинг, попытка чтения Supabase напрямую.
- **Скомпрометированная зависимость** — подмена `supabase.js`, установщика,
  стороннего CDN.
- **Инсайдер/админ** — злоупотребление правами; ограничивается аудитом.

## Границы доверия и потоки

```
Браузер ──HTTPS──> Cloudflare Worker ──HTTPS──> Render (aiohttp)
   │                                                │
   └──────HTTPS (Auth)──> Supabase Auth              └──service_role──> Supabase DB
Windows app ──HTTPS──> Render /api/license/check
Windows app ──HTTPS──> GitHub Releases (обновления, SHA-256)
```

- Всё, что приходит из браузера, недоверенно: тело, заголовки, Origin,
  `X-Forwarded-For`, токен.
- Worker не является средством авторизации: он лишь фильтрует маршруты,
  Origin и размер тела. Render обязан проверять всё сам.
- service_role не пересекает границу Render → Supabase.

## Угрозы и меры

| Угроза | Вектор | Мера |
| --- | --- | --- |
| Чтение чужих лицензий | Прямой REST-запрос к Supabase публичным ключом | RLS + удалённые политики + `revoke`; проверено: HTTP 401 |
| Покупка без входа | Гостевой checkout | `/api/checkout` требует валидный Supabase access_token |
| Чужой ключ в кабинете | Подмена `user_id`/`token` в claim | Сервер сверяет владельца заказа/ключа; чужое → 403/404 |
| Подделка суммы оплаты | Изменение `amount`/`plan` | Сумма сверяется с планом на сервере; ключ выдаётся по webhook/статусу ЮKassa |
| Перебор ключей/заказов | Массовые запросы | Rate-limit по IP и пользователю, токены ≥192 бит, `Retry-After` |
| Флуд checkout | Создание платежей | Лимит 20/IP и 5/пользователь в минуту |
| Кража сессии через XSS | Внедрение скрипта | CSP, экранирование вывода, SRI для `supabase.js`, никаких `eval` |
| Кража токена заказа из URL | Referer/история | Токен сразу переносится в localStorage и удаляется из адресной строки; `Referrer-Policy: no-referrer` |
| Подделка админки во фронтенде | Правка JS/HTML | Панель показывает только серверный `is_admin`; все `/api/admin/*` проверяют токен и email на сервере |
| Перебор админки | Чужой аккаунт | 403 на сервере, email должен быть подтверждён |
| Утечка ключей в логах | Логи Render | Ключи логируются только префиксом `XXXX-…` |
| Подмена Worker-запроса | Чужой Origin/метод | Allowlist Origin, только GET/HEAD/POST, лимит тела 16 КБ |
| Обход rate-limit через Worker | Все запросы с IP Worker | Worker перезаписывает `X-Forwarded-For` реальным `CF-Connecting-IP` |
| Подмена установщика | Ссылка на сторонний файл | Allowlist GitHub-релиза, обязательный SHA-256, лимит размера, повторная проверка перед запуском |
| Подмена `supabase.js` | Компрометация файла | SRI (SHA-384) на обеих страницах |
| Кликджекинг | iframe | `X-Frame-Options: DENY` на API; для статики — остаточный риск GitHub Pages |

## Допущения

- GitHub-аккаунт организации и Render/Supabase/Cloudflare защищены 2FA
  владельцем; это вне кода.
- ЮKassa присылает подписанные webhook-события; секрет не скомпрометирован.
- TLS-сертификаты площадок валидны; приложение не отключает проверку TLS.
- Пользователь не устанавливает сторонние патчи, отключающие проверки.
